# 原理、排查和版本适配

## 为什么使用已识别的槽位

原案例的搜狗 Linux 4.2.1.145 无法按预期直接识别新增的 Windows 自制 SSF。已识别的「尊贵黑金」包含原生 XML / SVG 布局，可在本地接入图片和新布局。工具因此读目标机器的官方资源，再生成修改副本，而不是分发整套官方文件。

这是一条可复用的适配路径，并不意味着所有搜狗版本都必须使用同一种入口。遇到提供官方自定义导入功能的版本，应先检查其原生能力。

## ZIP 格式

本案例实际核对的皮肤元数据摘要为：

```text
MD5(ZIP 的前 50 字节 + ZIP 总长度的 32 位小端编码)
```

构建器保留第一条本地 ZIP 记录，分别保留本地和中央目录扩展字段，重压缩内容并加入储存方式的填充成员，以保持前 50 字节和总长度；同时验证 ZIP CRC 和未修改成员的内容。重定位图片路径时仅重写相关 SVG 和填充成员，保留其他压缩记录。

这个摘要是该构建的资源格式要求，不是完整文件密码学签名，也不是隐私或可信性保证。项目另外使用 SHA-256 记录完整源 ZIP、核心库、补丁和生成文件。资源指纹相同不能证明两个 ZIP 内容相同。其他构建应重新检查，不要直接假定算法不变。

## 两个原生修复

`status_screen_fix.c` 截获 `n_sgxx::GetScreenSize(int*, int*)`，只在调用方为 `t_uiWrapper::MoveStatus(int,int)` 时修正外层屏幕尺寸限制；内部 `MoveWnd` 继续处理屏幕边界。其他候选框调用方使用原函数。

`v_mode_fix.c` 截获 `t_uiWrapper::UpdateComp()`，读取该构建已核对的强制竖排状态，在普通 XML 和 V 模式 XML 间切换。它涉及原生结构偏移、C++ 符号和函数地址；源码开头说明了约束。补丁不记录按键或改写输入内容。

启动器只在核心库和补丁 SHA-256 匹配时预加载；函数偏移检查是附加保护，不能代替核心库校验。不要把 `.so` 加入 `/etc/ld.so.preload`，也不要给所有桌面应用设置全局 `LD_PRELOAD`。

## 适配新版本的顺序

1. 记录实际搜狗版本、核心库哈希、Fcitx、X11/Wayland、架构、缩放和多屏布局。
2. 备份本机皮肤和相关配置，确认普通官方皮肤本来能正常显示。
3. 读取新版本 XML、图片引用、元数据和 ZIP 格式，核对槽位与控件名称。
4. 先只做资源层换肤；逐项验证透明、尺寸、文本位置、长候选及 V 模式。
5. 只有复现状态栏回弹或 V 布局切换问题时，才检查是否需要原生补丁。
6. 核对新版本符号、调用约定、结构偏移和窗口接口，修改并重新编译补丁；不能只改白名单或哈希。
7. 在隔离环境验证中文输入、删除、翻页、中英切换、状态栏按钮、跨屏、缩放、重载、登录自启和回退。
8. 保存新的 profile、源码差异和完整版本，区分“方法已适配”和“原二进制直接兼容”。

## 给 AI 的适配提示词

> 请参考此项目，为本机 Ubuntu 搜狗输入法适配自定义皮肤。先读取实际搜狗版本、核心库、Fcitx、显示协议、架构与缩放，备份本机皮肤并复现问题。优先调查本版本的官方换肤入口；需要复用槽位时，核对资源元数据、ZIP 格式、XML 控件和图片路径。先生成副本或隔离预览，不影响当前输入。原生补丁仅在确有需要时适配，必须核对函数符号、结构偏移并重新编译，不得直接绕过版本或哈希校验。测试普通拼音、长候选、V 模式、中英切换、状态栏按钮、屏幕底部、双屏与缩放。确认效果后再应用，保留备份和可验证的回退。第三方素材仅在其授权范围内使用，不上传个人配置或未经授权的图片。
